## The Problem: RestClient Is Verbose

In [12.3 Service Registration and Discovery with Eureka](<12.3. Service Registration and Discovery with Eureka.md>), calling another service with `DiscoveryClient` plus `RestClient` meant repeating the same boilerplate everywhere: get instance, get URI, build request, retrieve, deserialize.

```java
// Inventory Service calling Order Service: too much boilerplate
ServiceInstance orderService = discoveryClient
    .getInstances("order-service")
    .getFirst();

URI uri = orderService.getUri();

return restClient.get()
    .uri(uri + "/orders/core/helloOrders")
    .retrieve()
    .body(String.class);
```

---

## The Solution: OpenFeign

A declarative HTTP client originally created by Netflix (like Eureka). You write an interface that looks like a controller, and Spring handles the HTTP, service discovery, and load balancing behind the scenes, reducing the call above to one line:

```java
ordersFeignClient.helloOrders();
```

Load balancing is split by traffic direction, and you refer to services by name, not IP and port:

| Traffic Type      | Handled By                                                              |
| ----------------- | ----------------------------------------------------------------------- |
| Client to Service | API Gateway (distributes across service instances)                      |
| Service to Service | OpenFeign plus Spring Cloud LoadBalancer (distributes across targets)   |

---

## Setup

Add the dependency to any service that needs to call another service, then enable Feign clients on the main class.

```xml
<dependency>
    <groupId>org.springframework.cloud</groupId>
    <artifactId>spring-cloud-starter-openfeign</artifactId>
</dependency>
```

```java
@SpringBootApplication
@EnableFeignClients
public class InventoryServiceApplication {
    public static void main(String[] args) {
        SpringApplication.run(InventoryServiceApplication.class, args);
    }
}
```

---

## Creating a Feign Client

A Feign client is an interface that mirrors the target service's API:

```java
@FeignClient(name = "order-service", path = "/orders")
public interface OrderFeignClient {

    @GetMapping("/core/helloOrders")
    String helloOrders();
}
```

| Part                            | What It Does                                                     |
| ------------------------------- | --------------------------------------------------------------- |
| `@FeignClient`                  | Marks this interface as a Feign client                           |
| `name = "order-service"`        | The target's `spring.application.name` (registered in Eureka)    |
| `path = "/orders"`              | Base path prefix for all methods in this client                  |
| `@GetMapping("/core/...")`      | The endpoint path, same as the target controller's mapping        |

Inject and call it like a local method; Feign uses `name` to resolve the address through Eureka, with no hardcoded URLs:

```java
@Service
@RequiredArgsConstructor
public class ProductService {

    private final OrderFeignClient orderFeignClient;

    public String fetchFromOrderService() {
        return orderFeignClient.helloOrders(); // one line, that is it
    }
}
```

## Real Example: Order Service Calls Inventory Service

When a user creates an order, Order Service calls Inventory Service (set up in [12.2 Setting Up the Order and Inventory Services](<12.2. Setting Up the Order and Inventory Services.md>)) to reduce stock.

**Feign client (in Order Service)**:

```java
@FeignClient(name = "inventory-service", path = "/inventory")
public interface InventoryFeignClient {

    @PutMapping("/products/reduceStocks")
    Double reduceStocks(@RequestBody OrderRequestDto orderRequest);
}
```

**Target controller (in Inventory Service)**:

```java
@RestController
@RequestMapping("/products")
@RequiredArgsConstructor
public class ProductController {

    private final ProductService productService;

    @PutMapping("/reduceStocks")
    public ResponseEntity<Double> reduceStocks(@RequestBody OrderRequestDto orderRequest) {
        Double totalPrice = productService.reduceStocks(orderRequest);
        return ResponseEntity.ok(totalPrice);
    }
}
```

**Service logic (in Inventory Service)**:

```java
@Service
@RequiredArgsConstructor
public class ProductService {

    private final ProductRepository productRepository;

    @Transactional
    public Double reduceStocks(OrderRequestDto orderRequest) {
        double totalPrice = 0;

        for (OrderItemRequestDto item : orderRequest.getItems()) {
            Product product = productRepository.findById(item.getProductId())
                .orElseThrow(() -> new RuntimeException(
                    "Product not found with id: " + item.getProductId()));

            if (product.getStock() < item.getQuantity()) {
                throw new RuntimeException(
                    "Insufficient stock for product: " + product.getTitle());
            }

            product.setStock(product.getStock() - item.getQuantity());
            totalPrice += item.getQuantity() * product.getPrice();
            productRepository.save(product);
        }

        return totalPrice;
    }
}
```

**DTOs**:

```java
// In Order Service
@Data
public class OrderItemRequestDto {
    private Long productId;
    private Integer quantity;
}

@Data
public class OrderRequestDto {
    private List<OrderItemRequestDto> items;
}

@Data
public class OrderResponseDto {
    private Long id;
    private List<OrderItemRequestDto> items;
    private BigDecimal totalAmount;
    private OrderStatus status;
}
```

**Order Service uses the Feign client**:

```java
@Service
@RequiredArgsConstructor
public class OrderService {

    private final InventoryFeignClient inventoryFeignClient;
    private final OrderRepository orderRepository;
    private final ModelMapper modelMapper;

    @Transactional
    public OrderResponseDto createOrder(OrderRequestDto orderRequest) {
        // 1. Call Inventory Service to reduce stock and get the total
        Double totalPrice = inventoryFeignClient.reduceStocks(orderRequest);

        // 2. Build the order
        Order order = modelMapper.map(orderRequest, Order.class);
        order.setTotalAmount(BigDecimal.valueOf(totalPrice));
        order.setStatus(OrderStatus.CONFIRMED);

        // Set the parent reference on each item
        for (OrderItem item : order.getItems()) {
            item.setOrder(order);
        }

        // 3. Save and return
        Order savedOrder = orderRepository.save(order);
        return modelMapper.map(savedOrder, OrderResponseDto.class);
    }
}
```

> **Note**: Inventory Service needs its own copy of `OrderRequestDto` and `OrderItemRequestDto` with the same field names. `OrderResponseDto` lives only in Order Service. See "DTOs Must Exist in Both Services" below.

## The Complete Flow

```
Client: POST /api/v1/orders/core/create-order
       │
       ▼
API Gateway (port 8080)
  → strips /api/v1, forwards to Order Service
       │
       ▼
Order Service (port 8081)
  → receives the order request
  → calls inventoryFeignClient.reduceStocks(orderRequest)
       │
       ▼
Feign asks Eureka: "Where is inventory-service?"
  → Eureka returns: 10.4.5.6:8082
       │
       ▼
Inventory Service (port 8082)
  → reduces stock for each product
  → returns the total price
       │
       ▼
Order Service
  → creates the order with the total
  → saves to the order DB
  → returns the order response to the client
```

## DTOs Must Exist in Both Services

Each microservice is a separate application with its own codebase, so they cannot share classes directly. DTOs used in Feign communication must exist in both services with matching field names:

```
order-service/dto/
  ├── OrderRequestDto.java           ← client sends (items only)
  ├── OrderResponseDto.java          ← client receives (Order Service only)
  └── OrderItemRequestDto.java       ← productId, quantity

inventory-service/dto/
  ├── OrderRequestDto.java           ← same field names as Order Service
  └── OrderItemRequestDto.java       ← same field names as Order Service
```

> **Note**:
> - Field names must match for JSON serialization. If they differ, map with `@JsonProperty`. The Inventory Service copy can have fewer fields; extras are ignored on deserialization.
> - Some teams extract a shared Maven module to avoid duplicate DTOs, but most keep services fully independent with their own copies (the standard microservices approach).

  ├── clients/

  ├── controller/

  ├── entity/
  └── dto/

## Production Considerations

**Set realistic timeouts**: the Feign defaults (10s connect, 60s read on the underlying client) are too generous; a slow downstream blocks caller threads. Configure per client:

```yaml
spring:
  cloud:
    openfeign:
      client:
        config:
          inventory-service:
            connect-timeout: 2000      # ms; fail fast if unreachable
            read-timeout: 5000         # ms; cap how long we wait
          default:
            connect-timeout: 2000
            read-timeout: 5000
```

**Propagate auth between services**: service-to-service calls should not be unauthenticated. Forward the caller's JWT via a `RequestInterceptor` so every hop is authenticated:

```java
@Configuration
public class FeignAuthConfig {

    @Bean
    public RequestInterceptor authForwardingInterceptor() {
        return template -> {
            ServletRequestAttributes attrs =
                (ServletRequestAttributes) RequestContextHolder.getRequestAttributes();
            if (attrs != null) {
                String authHeader = attrs.getRequest().getHeader("Authorization");
                if (authHeader != null) {
                    template.header("Authorization", authHeader);
                }
            }
        };
    }
}
```

Beyond those two:

- **Errors are not wrapped automatically**: a 4xx/5xx from the downstream surfaces as `FeignException`. Handle it in your `@RestControllerAdvice` (see [2.7 Exception Handling](<../02-spring-mvc-and-rest-apis/2.7. Exception Handling.md>)) so the caller gets a clean error, not a stacktrace.
- **Idempotency for retries**: if you add retry (see [12.6 Resilience4J](<12.6. Circuit Breaker, Retry and Rate Limiter with Resilience4J.md>)), only retry idempotent calls. For `POST` like create-order, require an `Idempotency-Key` so the downstream can dedupe.
- **Sync vs async**: Feign is synchronous; the caller blocks. For fire-and-forget or eventual consistency, prefer messaging (Kafka, covered in unit 14).

## RestClient vs OpenFeign

| Dimension         | RestClient                                  | OpenFeign                                  |
| ----------------- | ------------------------------------------- | ------------------------------------------ |
| Style             | Programmatic; build the request manually     | Declarative; write an interface            |
| Service discovery | Manual (`DiscoveryClient`)                  | Automatic (Eureka by name)                 |
| Load balancing    | Manual                                      | Automatic                                  |
| Boilerplate       | High (URI, headers, retrieve, deserialize)  | Minimal (one method call)                  |
| Feels like        | HTTP client code                            | Calling a local method                     |
| Use when          | External third-party APIs                   | Service-to-service within your system      |

## Q&A

1. **What is OpenFeign?** A declarative HTTP client. You define an interface annotated with `@FeignClient` and Spring generates the implementation at runtime, removing the `RestClient`/`RestTemplate` boilerplate for service-to-service calls.
2. **What does `@EnableFeignClients` do?** Scans for `@FeignClient` interfaces and registers them as proxy beans in the context, so they can be injected.
3. **How does Feign know which host to call?** The `name` on `@FeignClient` matches a `spring.application.name` in Eureka. Spring Cloud LoadBalancer resolves it to a live instance and balances across them.
4. **Why must DTOs be duplicated across services?** Each service is its own deployable and does not share a JAR. JSON serialization works as long as field names match; teams either duplicate or extract a shared `-common` module (at the cost of a coupling point).
5. **`@FeignClient` vs `@RestController`?** They use the same HTTP-mapping annotations but mean opposite things: `@RestController` implements an endpoint, `@FeignClient` consumes one. The annotations on a Feign interface describe the remote endpoint's shape.
6. **Should you retry every Feign call?** No, only idempotent ones (`GET`, `PUT`, `DELETE`). Retrying a `POST` like create-order can charge a user twice; require an `Idempotency-Key` for those or skip retry entirely.
