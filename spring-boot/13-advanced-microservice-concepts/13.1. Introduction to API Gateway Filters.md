Filters intercept, modify, and enhance requests and responses passing through the API Gateway. They handle cross-cutting concerns (authentication, logging, rate limiting) at one centralized entry point, before requests reach the microservices.

> **Reference**: this builds on the gateway project and routes from [12.4 Spring Cloud API Gateway](<../12-microservices/12.4. Spring Cloud API Gateway.md>); it adds filters on top of that setup.

---

## How Filters Work

```
      ┌────────────────────┐
      │   Gateway Client   │
      └────────┬─────▲─────┘
               │     │
      ┌────────▼─────┤─────┐
      │  Gateway Handler   │
      └────────┬─────▲─────┘
               │     │
      ┌────────▼─────┤─────┐
      │ Filter (order = -1)│
      ├────────────────────┤
      │ Filter (order = 0) │
      ├────────────────────┤
      │ Filter (order = n) │
      └────────┬─────▲─────┘
               │     │
      ┌────────▼─────┤─────┐
      │ Proxied Service    │
      │ (Order/Inventory)  │
      └────────────────────┘
```

A request flows down through filters (the pre phase). The response flows back up through the same filters in reverse (the post phase).

---

## Two Types of Filters

- **Global filter**: applies to every route. Implement the `GlobalFilter` interface.
- **Route-specific filter**: applies only to routes that opt in via YAML. Extend `AbstractGatewayFilterFactory`.

---

## Global Filter

Applied to every route. Good for logging, metrics, and common headers.

```java
@Component
@Slf4j
public class GlobalLoggingFilter implements GlobalFilter, Ordered {

    @Override
    public Mono<Void> filter(ServerWebExchange exchange, GatewayFilterChain chain) {

        // Pre phase: runs before the request reaches the service
        log.info("Global Pre: {}", exchange.getRequest().getURI());

        return chain.filter(exchange)
            .then(Mono.fromRunnable(() -> {
                // Post phase: runs after the response comes back
                log.info("Global Post: {}", exchange.getResponse().getStatusCode());
            }));
    }

    @Override
    public int getOrder() {
        return 5; // lower number runs first in pre, last in post
    }
}
```

| Part                            | What It Does                                                  |
| ------------------------------- | ------------------------------------------------------------- |
| `GlobalFilter`                  | Makes this a global filter, applied to all routes              |
| `Ordered`                       | Defines where in the chain this filter runs                    |
| `exchange`                      | Holds the request and response                                 |
| `chain.filter(exchange)`        | Passes control to the next filter (pre phase done)             |
| `.then(Mono.fromRunnable(...))` | Post phase: runs after the response returns                    |
| `Mono<Void>`                    | Reactive, non-blocking return type so concurrency is preserved |

```
Output:
  Global Pre: http://localhost:8080/api/v1/orders/core/helloOrders
  Global Post: 200 OK
```

## Route-Specific Filter (Gateway Filter)

Applied to specific routes only. Good for route-level authentication, transformations, and validations.

```java
@Component
@Slf4j
public class LoggingOrdersFilter extends
        AbstractGatewayFilterFactory<LoggingOrdersFilter.Config> {

    public LoggingOrdersFilter() {
        super(Config.class);
    }

    @Override
    public GatewayFilter apply(Config config) {
        return (exchange, chain) -> {
            log.info("Order Filter Pre: {}", exchange.getRequest().getURI());
            return chain.filter(exchange);
        };
    }

    public static class Config {
        // Add filter config properties here if needed
    }
}
```

| Part                           | What It Does                                          |
| ------------------------------ | ---------------------------------------------------- |
| `AbstractGatewayFilterFactory` | Base class for route-specific filters                 |
| `Config`                       | Inner class holding any custom filter properties      |
| `apply(Config config)`         | Returns the actual filter logic                       |
| `(exchange, chain) -> { }`     | Lambda implementing the `GatewayFilter` interface     |

### Register in Route Config

Add the filter name to the existing route from [12.4 Spring Cloud API Gateway](<../12-microservices/12.4. Spring Cloud API Gateway.md>):

```yaml
spring:
  cloud:
    gateway:
      routes:
        - id: order-service
          uri: lb://ORDER-SERVICE
          predicates:
            - Path=/api/v1/orders/**
          filters:
            - StripPrefix=2
            - name: LoggingOrdersFilter    # must match the factory name
```

> **Note**: the filter name in YAML must match the factory name (Spring derives it from the class name, stripping a trailing `GatewayFilterFactory` if present). Only this route gets the filter; the inventory route is unaffected.

## Global vs Route-Specific

```
Request to /api/v1/orders/**:
  → Global Filter (all routes)
  → LoggingOrdersFilter (order route only)
  → Order Service

Request to /api/v1/inventory/**:
  → Global Filter (all routes)
  → Inventory Service
  (no LoggingOrdersFilter; it is not on this route)
```

## What You Can Do in Filters

Everything works off the `exchange` object, which exposes the request (pre phase) and response (post phase):

```java
// Read request info
exchange.getRequest().getURI();
exchange.getRequest().getPath();
exchange.getRequest().getHeaders();
exchange.getRequest().getQueryParams();
exchange.getRequest().getMethod();

// Modify the request (add headers, change path)
exchange.getRequest().mutate()
    .header("X-Custom-Header", "value")
    .build();

// Read response info (post phase only)
exchange.getResponse().getStatusCode();
exchange.getResponse().getHeaders();
```

## Q&A

1. **What is a Gateway Filter and why use one?** A filter intercepts requests and responses at the gateway to handle cross-cutting concerns (auth, logging, rate limiting) in one place instead of duplicating them across every microservice.
2. **Difference between `GlobalFilter` and `AbstractGatewayFilterFactory`?** `GlobalFilter` applies to every route automatically. `AbstractGatewayFilterFactory` creates a named filter you opt into per route via YAML, useful when behavior should vary by route.
3. **What do pre and post phases mean?** Pre runs before the request reaches the downstream service (on the way down the chain); post runs after the response returns (on the way up). Post logic is attached via `chain.filter(exchange).then(...)`.
4. **How is filter ordering controlled?** Implement `Ordered` and return an `int` from `getOrder()`. Lower numbers run first in the pre phase and last in the post phase.
5. **Why is the return type `Mono<Void>`?** Spring Cloud Gateway is built on Spring WebFlux (reactive, non-blocking), so filters return reactive types and the gateway handles many concurrent requests without blocking threads.

## Quick Revision Cheat Sheet

| Concept               | Remember                                                          |
| --------------------- | ----------------------------------------------------------------- |
| Global filter         | `implements GlobalFilter, Ordered`; auto-applied to all routes     |
| Route-specific filter | `extends AbstractGatewayFilterFactory<Config>`; opt-in per route    |
| Pre vs post           | pre = before downstream; post = `chain.filter(...).then(...)`       |
| Order                 | Lower number runs first in pre, last in post                      |
| YAML filter name      | Factory name; Spring strips a trailing `GatewayFilterFactory`      |
| Reactive type         | `Mono<Void>` (WebFlux); never block inside a filter               |
